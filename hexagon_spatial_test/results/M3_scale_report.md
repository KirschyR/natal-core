# M3 报告（CPU 侧）：宽核/大规模迁移 CSR 折叠实测

> 依据：`Hex_model_recon.md` §5（M3）、§4（硬瓶颈表）；`EVALUATE.md` §6。
> 范围：**仅 CPU 侧**（GPU 按用户决定待确认后另做）。风险分类：局部（复现脚本 + 数据），未改产品代码。
> 数据：`results/m3_scale_data.json`；命令：`python repro/m3_scale_probe.py`（约 8 min，峰值 RSS 6.69 GB）。

## 1. 方法

- 场地 `rows=cols ∈ {30,60,120,300}`；核尺寸 `k ∈ {3,5,11,21,51}`；`sigma=1.5`（最坏情形，全部
  `k²` 项非零）。
- 对每个组合测：核支持数 `support`、CSR 折叠耗时 `fold_s`、`nnz`、CSR 字节数、总体
  `build_s`（`SpatialPopulation.builder(...).build()`）、deterministic CPU `tick_s`（`run(3)` 平均）。
- CSR 字节 = `indptr(int64) + dest_idx(int64) + weights(float64)` = `16·nnz + 8·(n_demes+1)`。
- 预算 `1.2 GB`：CSR 超过则**显式标记**为 skipped（不静默），仍记录 fold/nnz/内存。
- 另测「论文核」（`size=51`、`mean_dispersal=avd∈{0.5,1,2}`）在 300² 下的支持/nnz/内存。

即便论文真实 `avd=1.0` 核（`d≤25` 之外 underflow 截断后 support=2349），300² 也已达 **3.1 GB CSR / 56 s 构建**。

## 4. 关键结论（M4 决断输入）

1. **CSR 折叠是纯 Python、随 nnz 线性**：吞吐约 **3.3–3.6e6 entries/s**；300²×51² 需 **60 s**，
   论文核 avd=1.0 需 **56 s**。
2. **内存墙**：`CSR ≈ 16·nnz B`。300²×51² = 3.4 GB；论文核 avd=1.0 = 3.1 GB。若外推海南
   `2599×2601`（6.8e6 demes、r25 盘 ~1951 支持）→ `nnz ≈ 1.3e10`，`CSR ≈ 200 GB`，
   折叠 ≈ 64 min——**CPU 侧不可行**（recon §4 的预判被实测确认）。
3. **CPU tick 亦随 nnz 线性且昂贵**：大网格约 `~6e-7 s / CSR entry / tick`。300²×21²
   （nnz 3.8e7）已 **24.9 s/tick**；外推论文核 avd=1.0（nnz 1.95e8）约 **2 min/tick**。
   宽核下 CPU 每代成本使论文规模（数十–上百代）不现实。
4. **显式预算**：probe 对超 1.2 GB 的 CSR 显式标记 skipped；但 natal **CPU 路径本身无内存预算守卫**
   （`migration_cache_bytes` 仅用于 GPU）——建议 M4 一并考虑显式预算/报错。
5. 与 recon §4 表对比：其「300² r25 disk CSR ~5.9 GB」在本实现口径（16 B/entry）下实测
   300²×51²=3.4 GB、论文核 avd=1.0=3.1 GB，量级一致。
